## Data provenance and rights

The Premier League's [website terms](https://www.premierleague.com/en/terms-and-conditions) explicitly prohibit reusing the site content to create a database without approval. We therefore **did not scrape or copy the official 2026/27 squad lists** into our game database. Those lists are useful as fact-checking references for our research.

- Player/team candidate discovery uses **Wikidata's CC0 structured data**.
- Its `P54` statements show possible club membership, not proof of a competitive senior appearance.
- For a player to count in a standard FOOTY "played for" answer, require evidence of at least one **senior competitive first-team appearance**. Loans count if played; youth/reserve teams are separate.
- A premium data provider may be needed to establish complete appearances and registrations reliably. Confirm rights and historical/current coverage before buying a license.
- Match registrations, youth eligibility, squad numbers, transfer announcements, membership statements and appearances are **different evidence types**. Do not collapse them into one eligibility boolean.

## What we added to Supabase

`supabase/v14_epl_2026_27_schema.sql` documents the new private schema snapshot already applied:

- `competition_seasons` — one competition + one campaign;
- `season_snapshots` — point-in-time record with as-of date and phase;
- `season_club_participants` — which clubs compete in the season;
- `season_player_evidence` — **unapproved** player/club candidates and source evidence;
- `season_transfer_events` — transfer facts with prior/new club, date, type and source;
- `season_game_modes` — feature flag; cannot enable if coverage incomplete.

All tables have RLS enabled; anonymous clients have no schema access. Supabase is not powering live gameplay yet.

`scripts/seed-epl-2026-27.sql` is the idempotent seed: 20 clubs, 3 pending example transfers, a disabled game mode.

## New Transfer Mode: preliminary product specification

Two candidate question formats:

1. **Summer arrivals** — "Name a player who joined Arsenal during the summer 2026 transfer window." This is an **open-ended** question. It must NOT launch until arrival coverage for the target club/window is reviewed complete, including transfers, loans and free-agent moves subject to clearly published rules.
2. **Transfer trail** — "Which club did [player] leave to join Arsenal in summer 2026?" A specific verified transfer can support this without needing an exhaustive whole-league answer list. Avoid ambiguous cases (multiple source clubs, loans, transfers announced but collapsed).

Design rules: `snapshot_date=2026-11-04` covers only known facts *as of that date*, and a new later snapshot should be created after the January 2027 window rather than overwriting the earlier answers. The official summer window ran June 15–September 1, 2026. January deals do NOT belong in Summer 2026 mode.

Three test events are present for Bruno Guimarães (Newcastle → Arsenal), Ezri Konsa (Aston Villa → Arsenal) and James Trafford (Manchester City → Leeds). These are **research cases**, not yet approved questions. Reference reports: [Sky Sports summer deals](https://www.skysports.com/football/news/13546618/transfer-news-summer-transfer-window-2026-premier-league-deals-ins-and-outs), [Fantasy Football Scout confirmed transfers](https://www.fantasyfootballscout.co.uk/fpl-2026-27-transfer-news-confirmed-summer-signings), [PL analysis](https://www.premierleague.com/en/news/4681361).

## First player-data research workflow

Files:

- `data/seasons/epl-2026-27-prejanuary.json`: fixed 20-club manifest, all 20 independently matched Wikidata club QIDs;
- `src/lib/epl-season.js`: validates manifest, parses SPARQL, exports SQL that ONLY writes pending `season_player_evidence`;
- `scripts/research-epl-2026-27.js`: bounded, read-only Wikidata API research;
- `.github/workflows/epl-season-research.yml`: manually triggered; produces a downloadable ZIP artifact;
- `tests/epl-season.test.js`: guards against wrongly promoting membership to a senior appearance.

### Step A: All 20 club QIDs verified (2026-11-04)

The original 16-club discovery export failed, and its exact job-log error was not available through the repository connection. Instead, we independently matched all 16 club entities to their canonical Wikidata item pages and saved the verified mappings in GitHub and Supabase. The `discover_teams` workflow is now effectively an offline mapping report: it makes **zero** search API calls because every team already has a verified QID. It is no longer a prerequisite for moving ahead.

The workflow has been improved to save test and export logs to an artifact even if a future request fails.

### Step B: collect first player membership candidates

In the same workflow, choose `discover_players` and enter any one of the 20 mapped club IDs, such as `club_arsenal`.

The workflow calls Wikidata Query Service once for that club and preserves possible 2026/27 membership relationships. It has a 250-row cap; reaching the cap flags likely truncation rather than claiming completeness. Rows with missing time qualifiers remain pending, even if they appear active.

Download the JSON and SQL artifacts. **Do not run the SQL automatically**: review QIDs, source dates and potential reserve/youth records first. The SQL only stages research candidates; it never changes approved career records, scores or daily challenges.

Wikidata respects client limits: [Wikidata Data Access](https://www.wikidata.org/wiki/Help:Data_access) and [WDQS usage limits](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual).

## Record preservation and question-time filtering — revised V14 decision

The founder chose to **keep every legally reusable observed claim**, even if it is old, undated, or from a different competition. No source evidence is discarded just because it is not an eligible answer to today's question.

In the [first Arsenal player discovery run](https://github.com/mvxmvxmvx/FOOTY/actions/runs/41954990496), **182 distinct P54 claims** were exported; **143 have no start-date qualifier**. They are still valuable as raw history but cannot prove a 2026/27 men's first-team competitive appearance. The exporter's generated `-stage.sql` now includes **all** pending claims; dated and undated review files are only triage subsets, not inclusion rules.

This snapshot ID records the date/context of *research*, not a claim of 2026/27 league appearance. A question-specific, approved evidence filter determines eligibility. See [full archive, eligibility and rarity design](V14-knowledge-and-rarity.md) for the six rarity tiers and publication gates.

**Current documentation does not assert these 182 records have been applied to Supabase**; the run artifact is export-only, and importing the staged SQL is a separate step requiring verification. New transfer mode stays disabled.
